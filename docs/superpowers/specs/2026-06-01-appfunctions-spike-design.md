# AppFunctions Spike — Expose Billboard Hot 100 #1 to Gemini App

**Date:** 2026-06-01
**Status:** Design — awaiting user review
**Scope:** Test-only spike. Minimum viable surface to verify end-to-end that the Gemini app on a Galaxy S25 can invoke a `@AppFunction` exposed by the Billboard app and receive the current Hot 100 #1 song from our live Retrofit data — including from a cold-started app process.

## Goals (and Non-Goals)

**Goals**
- Expose exactly one `@AppFunction` (`getCurrentHot100TopSong`) from the Billboard app.
- Cold-boot DI works: when the system spawns our process to invoke the function, Hilt provides the existing `:core:domain` UseCase that ultimately calls Retrofit.
- Verify discovery (`adb shell cmd app_function list-app-functions`) and end-to-end invocation from the Gemini app (natural-language query → our function → Gemini-rendered answer).
- One PR, smallest possible diff.

**Non-Goals**
- No ADK integration in this app (Gemini app owns orchestration + Nano).
- No in-app chat UI / no `:feature:agent` module.
- No A2UI renderer.
- No multi-function surface (Top 10, search, collection mutations — all out of scope for the spike).
- No fallback for non-Android-16 devices in this spike — `minSdk` bump is accepted as a known break.

## Verified Facts (from spike research)

- `androidx.appfunctions:1.0.0-alpha09` (May 2026). Three artifacts:
  - `appfunctions` (client)
  - `appfunctions-service` (server-side — what we add)
  - `appfunctions-compiler` (KSP, code-gen)
- `AppFunctionManagerCompat` requires Android 16+ (API 36). Current project `minSdk = 32` → must bump to `36`.
- Provider interface is **`AppFunctionConfiguration.Provider`** (not `AppFunctionFactory.Provider` as the original guide claimed).
- KSP arg `appfunctions:aggregateAppFunctions = true` must be set once at the app module.
- Per-app-function permission for callers: `android.permission.EXECUTE_APP_FUNCTIONS` (Gemini app already holds it).
- Manifest registration is generated by the KSP compiler — no manual `<service>` / `<meta-data>` entry expected for this minimal case.
- Gemini app calling third-party AppFunctions is live in 2026 on Samsung OneUI 8.5+ (S25/S26) and Pixel 9+, but Google describes the developer ecosystem as "a small set of app developers" — automatic discovery by the Gemini app for arbitrary third-party functions is **not guaranteed**. This is the spike's primary unknown.

## Architecture

Single-PR layering, no new modules:

```
:app
  ├── BillboardApplication (existing @HiltAndroidApp)
  │     └─ NEW: implements AppFunctionConfiguration.Provider
  └── appfunctions/
        └─ BillboardFunctions.kt (NEW, @Inject constructor)
              └─ depends on existing :core:domain UseCase

:core:domain
  └── existing GetBillboardHot100UseCase (reused as-is — no new UseCase)
        signature: suspend operator fun invoke(): ChartOverview
        ChartOverview.chartList: List<Chart>  (Chart has rank/title/artist)

:core:data-impl / :core:data-source/prod
  └── existing ChartRepository + Retrofit (reused as-is)
```

Cold-boot flow (verified-by-design, not yet runtime-tested):

```
Gemini app  ──(AppSearch index)──▶  system AppFunction service
                                          │
                                          ▼
                              spawn billboard process (cold)
                                          │
                                          ▼
                       BillboardApplication.onCreate()  ← Hilt graph built
                                          │
                                          ▼
                     appFunctionConfiguration getter invoked
                                          │
                                          ▼
       AppFunctionConfiguration.Builder
         .addEnclosingClassFactory(BillboardFunctions::class.java) { billboardFunctions }
                                          │
                                          ▼
                    generated dispatcher calls BillboardFunctions.getCurrentHot100TopSong(...)
                                          │
                                          ▼
                          GetChartUseCase → ChartRepository → Retrofit
                                          │
                                          ▼
                       TopSong returned ──▶  Gemini app  ──▶  Nano renders answer
```

## Changes

### 1. `gradle/libs.versions.toml`
- Add `appfunctions = "1.0.0-alpha09"` version.
- Add three library entries: `androidx-appfunctions`, `androidx-appfunctions-service`, `androidx-appfunctions-compiler`.
- Bump `minSdk = "32"` → `"36"`.
- Bump `appVersionCode 7 → 8`, `appVersionName "1.2.0" → "1.3.0-spike"` (or whatever release flow prefers — to be decided at release time, not in spike PR).

### 2. `app/build.gradle.kts`
- Add KSP top-level arg: `ksp { arg("appfunctions:aggregateAppFunctions", "true") }`.
- Add three new dependencies (the `appfunctions-compiler` via `ksp(...)`).

### 3. `app/src/main/java/com/hancekim/billboard/BillboardApplication.kt`
- Implement `AppFunctionConfiguration.Provider`.
- Add `@Inject lateinit var billboardFunctions: BillboardFunctions`.
- Override `appFunctionConfiguration` to wire `BillboardFunctions` into the configuration.

### 4. `app/src/main/java/com/hancekim/billboard/appfunctions/BillboardFunctions.kt` (NEW)
- `class BillboardFunctions @Inject constructor(private val getBillboardHot100UseCase: GetBillboardHot100UseCase)`.
- `@AppFunctionSerializable data class TopSong(title, artist, rank)` with KDoc.
- `@AppFunction suspend fun getCurrentHot100TopSong(context: AppFunctionContext): TopSong`.
- Implementation: `getBillboardHot100UseCase().chartList.firstOrNull { it.rank == 1 }` → map to `TopSong`.
- Throws `AppFunctionElementNotFoundException` if no rank-1 entry (defensive — should not happen).

> Comments in this file will be written in Korean per project rule (`CLAUDE.md` language rules).

## Module-Boundary Note

The new file lives in `:app` (not in a feature module), so no `:core:domain` → `:core:data` boundary is crossed. `BillboardFunctions` injects only `GetChartUseCase` — same layering rule as Presenters.

## Verification Steps (post-merge, on Galaxy S25)

1. `./gradlew :app:assembleProdDebug`
2. Install to S25 (OneUI 8.5+ / Android 16).
3. `adb shell cmd app_function list-app-functions | grep com.hancekim.billboard`
   - **Pass:** the function id `getCurrentHot100TopSong` appears.
   - **Fail:** indexing did not happen — investigate KSP schema output + manifest.
4. Open Gemini app, ask: "What's the current #1 song on the Billboard Hot 100?"
   - **Pass:** Gemini answers with the live chart's #1 title + artist.
   - **Partial fail (function not discovered):** Gemini answers from its own training data. Investigate (a) whether Gemini app needs an explicit "connect" or category gating, (b) whether Google requires Play Console enrollment.
5. Force-stop the app, then repeat step 4 to verify cold-boot path.

## Known Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Gemini app does not auto-discover third-party functions outside Google's allowlist | **Medium-high** — Google explicitly described it as a "small set of app developers" | If discovery fails, the spike's deliverable becomes a documented finding ("requires X enrollment") rather than a working demo. ADB list verification still proves our side is correct. |
| `androidx.appfunctions` alpha API changes before next quarter | Medium | Pin exact alpha09; revisit on each bump. |
| `minSdk = 36` breaks existing users | Certain | Accepted for spike branch; do **not** merge spike to `develop` unless we agree to ship the bump. Alternative: gate AppFunctions wiring behind a per-flavor build variant if we want to keep `prod` on `minSdk 32`. |
| Retrofit call hangs / fails during cold-boot invocation | Low | `runCatching` + `AppFunctionElementNotFoundException` on failure — fail fast so Gemini app surfaces the error. |
| KSP `aggregateAppFunctions` must be set at the *terminal* (app) module, not in convention plugin | Low | Place the `ksp { arg(...) }` block directly in `app/build.gradle.kts`, not in any convention plugin. |

## Open Questions (decide at code time, not now)

- Should `appfunctions-service` be added in a new `billboard.android.appfunctions` convention plugin, or inline in `app/build.gradle.kts`? **Recommendation: inline.** Convention plugins are for cross-module reuse; this is a one-shot in `:app`.
- Real minSdk floor for `appfunctions-service` may actually be 34 (per `AppFunctionManagerCompat U+` note) rather than 36 — the `/ai/appfunctions` page asserted 16+. Going with 36 to match the most recent doc claim; revisit if the alpha09 AAR manifest reveals a lower floor.
